# 要件定義書

## プロジェクト概要

**プロジェクト名:** Flask + MySQL ToDo アプリケーション

**目的:**
Flask と MySQL を使用して、認証機能付きのToDoリスト管理アプリケーションを構築する。
Webアプリケーション開発の基礎（認証、CRUD、セキュリティ）を学習する。

**対象ユーザー:**
-個人でタスク管理をしたいユーザー
-Webアプリケーション開発を学習したい開発者

**開発期間:** 4週間

---

## 機能要件

### 1. ユーザー管理

#### UC-01: ユーザー登録
**概要:** 新規ユーザーがアカウントを作成できる

**アクター:** 未登録ユーザー

**事前条件:** なし

**基本フロー:**
1.ユーザーが「ユーザー登録」ページにアクセス
2.以下の情報を入力
   -ユーザー名（3〜20文字、英数字とアンダースコア）
   -メールアドレス（有効な形式）
   -パスワード（8文字以上）
   -パスワード確認（パスワードと一致）
3.「登録」ボタンをクリック
4.システムがバリデーションを実行
5.問題なければユーザーを作成
6.ログインページにリダイレクト
7.成功メッセージを表示

**代替フロー:**
-バリデーションエラー: エラーメッセージを表示
-ユーザー名重複: 「このユーザー名は既に使用されています」
-メール重複: 「このメールアドレスは既に登録されています」

#### UC-02: ログイン
**概要:** 登録済みユーザーがログインできる

**アクター:** 登録済みユーザー

**事前条件:** ユーザーアカウントが存在する

**基本フロー:**
1.ユーザーが「ログイン」ページにアクセス
2.以下の情報を入力
   -ユーザー名またはメールアドレス
   -パスワード
   -（オプション）ログイン状態を保持
3.「ログイン」ボタンをクリック
4.システムが認証情報を検証
5.認証成功でセッションを作成
6.ToDoリストページにリダイレクト
7.ようこそメッセージを表示

**代替フロー:**
-認証失敗: 「ユーザー名またはパスワードが正しくありません」

#### UC-03: ログアウト
**概要:** ログイン中のユーザーがログアウトできる

**アクター:** ログイン済みユーザー

**事前条件:** ユーザーがログインしている

**基本フロー:**
1.ユーザーが「ログアウト」をクリック
2.システムがセッションを削除
3.トップページにリダイレクト
4.ログアウトメッセージを表示

### 2. ToDo管理

#### UC-04: ToDo作成
**概要:** ユーザーが新しいToDoを作成できる

**アクター:** ログイン済みユーザー

**事前条件:** ユーザーがログインしている

**基本フロー:**
1.ユーザーが「新規作成」ボタンをクリック
2.作成フォームが表示される
3.以下の情報を入力
   -タイトル（必須、1〜100文字）
   -説明（任意、500文字以内）
4.「保存」ボタンをクリック
5.システムがバリデーションを実行
6.ToDoを作成
7.ToDoリストにリダイレクト
8.成功メッセージを表示

**代替フロー:**
-バリデーションエラー: エラーメッセージを表示

#### UC-05: ToDo一覧表示
**概要:** ユーザーが自分のToDoリストを閲覧できる

**アクター:** ログイン済みユーザー

**事前条件:** ユーザーがログインしている

**基本フロー:**
1.ユーザーがToDoリストページにアクセス
2.自分のToDoが表示される
3.各ToDoには以下が表示される
   -チェックボックス（完了/未完了）
   -タイトル
   -説明（先頭100文字）
   -作成日時
   -編集ボタン
   -削除ボタン

**フィルター機能:**
-全て: 全てのToDoを表示
-未完了: 未完了のToDoのみ表示
-完了: 完了したToDoのみ表示

#### UC-06: ToDo詳細表示
**概要:** ユーザーがToDoの詳細を閲覧できる

**アクター:** ログイン済みユーザー

**事前条件:**
-ユーザーがログインしている
-ToDoが存在する

**基本フロー:**
1.ユーザーがToDoのタイトルをクリック
2.詳細ページが表示される
3.以下の情報が表示される
   -ステータス（完了/未完了）
   -タイトル
   -説明（全文）
   -作成日時
   -更新日時
   -編集ボタン
   -削除ボタン

#### UC-07: ToDo編集
**概要:** ユーザーが既存のToDoを編集できる

**アクター:** ログイン済みユーザー

**事前条件:**
-ユーザーがログインしている
-自分のToDoである

**基本フロー:**
1.ユーザーが「編集」ボタンをクリック
2.編集フォームが表示される（現在の値がセット済み）
3.情報を変更
4.「更新」ボタンをクリック
5.システムがバリデーションを実行
6.ToDoを更新
7.詳細ページにリダイレクト
8.成功メッセージを表示

**代替フロー:**
-他人のToDo: 403エラー

#### UC-08: ToDo削除
**概要:** ユーザーがToDoを削除できる

**アクター:** ログイン済みユーザー

**事前条件:**
-ユーザーがログインしている
-自分のToDoである

**基本フロー:**
1.ユーザーが「削除」ボタンをクリック
2.確認ダイアログが表示される
3.「OK」をクリック
4.ToDoを削除
5.リストページにリダイレクト
6.削除メッセージを表示

**代替フロー:**
-キャンセル: 削除せずに元の画面に戻る

#### UC-09: ToDo完了/未完了切り替え
**概要:** ユーザーがToDoの完了状態を切り替えられる

**アクター:** ログイン済みユーザー

**事前条件:**
-ユーザーがログインしている
-自分のToDoである

**基本フロー:**
1.ユーザーがチェックボックスをクリック
2.完了状態が切り替わる
3.リストページが更新される
4.ステータスメッセージを表示

## 非機能要件

### 1. セキュリティ

#### パスワードセキュリティ
-パスワードはbcryptでハッシュ化して保存
-平文パスワードは保存しない
-パスワードは8文字以上

#### セッション管理
-セッションCookieはHttpOnly属性を設定
-セッションの有効期限は24時間（サーバー側でも設定可能）
-ログアウト時はセッションを完全に削除

#### CSRF対策
-全てのPOST/PUT/DELETEリクエストにCSRFトークンを使用
-Flask-WTFのCSRF保護を有効化

#### XSS対策
-ユーザー入力は全てエスケープ
-Jinja2の自動エスケープを使用

#### SQLインジェクション対策
-SQLAlchemy ORMを使用
-生SQLは使用しない

#### アクセス制御
-未ログインユーザーはToDoページにアクセスできない
-自分のToDoのみ閲覧・編集・削除可能

### 2. パフォーマンス

-ページ読み込み時間: 2秒以内
-データベースクエリ: N+1問題を避ける
-インデックス: user_id、(user_id, completed)

### 3. 可用性

-稼働率: 99%以上（学習用なので目標値）
-エラー発生時は適切なエラーメッセージを表示

### 4. 保守性

-コードカバレッジ: 80%以上
-ドキュメント: 全機能にドキュメントを用意
-コーディング規約: PEP 8準拠

### 5. ユーザビリティ

-レスポンシブデザイン（Bootstrap使用）
-明確なエラーメッセージ
-操作後のフィードバック（フラッシュメッセージ）

## データモデル

### ER図

**ER図（データベース構造）:**

    users (ユーザー)
      ├─ id (主キー)
      ├─ username (ユーザー名, UNIQUE)
      ├─ email (メールアドレス, UNIQUE)
      ├─ password_hash (パスワードハッシュ)
      ├─ created_at (作成日時)
      └─ updated_at (更新日時)
      │
      │ 1対多の関係
      ↓
    todos (ToDo)
      ├─ id (主キー)
      ├─ title (タイトル)
      ├─ description (説明)
      ├─ completed (完了フラグ)
      ├─ user_id (外部キー → users.id)
      ├─ created_at (作成日時)
      └─ updated_at (更新日時)


### テーブル定義

#### users

| カラム名 | 型 | 制約 | 説明 |
|----------|-----|------|------|
| id | INT | PRIMARY KEY, AUTO_INCREMENT | ユーザーID |
| username | VARCHAR(80) | NOT NULL, UNIQUE | ユーザー名 |
| email | VARCHAR(120) | NOT NULL, UNIQUE | メールアドレス |
| password_hash | VARCHAR(255) | NOT NULL | ハッシュ化パスワード |
| created_at | DATETIME | NOT NULL | 作成日時 |
| updated_at | DATETIME | NOT NULL | 更新日時 |

#### todos

| カラム名 | 型 | 制約 | 説明 |
|----------|-----|------|------|
| id | INT | PRIMARY KEY, AUTO_INCREMENT | ToDo ID |
| title | VARCHAR(100) | NOT NULL | タイトル |
| description | TEXT | NULL | 説明 |
| completed | BOOLEAN | NOT NULL, DEFAULT FALSE | 完了フラグ |
| user_id | INT | NOT NULL, FOREIGN KEY | ユーザーID |
| created_at | DATETIME | NOT NULL | 作成日時 |
| updated_at | DATETIME | NOT NULL | 更新日時 |

### リレーションシップ

-**User → Todo**: 1対多（One to Many）
-外部キー: `todos.user_id` → `users.id`
-カスケード: `ON DELETE CASCADE`

## 制約事項

### 技術的制約
-Python 3.11以上
-MySQL 8.0以上
-モダンブラウザ（Chrome、Firefox、Safari、Edge）

### 機能的制約
-1ユーザーあたりのToDo数: 制限なし（実質的には性能による）
-ファイル添付機能なし
-共有機能なし
-通知機能なし

### 時間的制約
-開発期間: 4週間
-Phase 1での実装範囲に限定
